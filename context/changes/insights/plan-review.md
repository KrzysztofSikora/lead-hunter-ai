## Decisions the PR reviewer should look at
- D-6: a new `WORK` event type and `metadata_json` shape in `activity_events`, plus a new public route. This is a stored-data decision, and option B (a `work_entries` table) is the real alternative.
- D-4: the reply-rate cohort and what counts as `noReply` (now `LOST`/`REJECTED`/`EXPIRED`). This is the metric the operator will read most, and a past week's rate can still change.
- D-1/D-10: the public `Insights` response shape (see finding 2).

## What is good

The ISO facts are correct: 2026-12-31 and 2027-01-01 are in 2026-W53, 2027-W01 starts on 2027-01-04, and W44 runs from 26 October to 1 November.
- Each number comes only from facts that are already stored, so no backfill is needed. The D-4 cohort with an explicit `awaiting` count honours §10.3 "nie zakłada porażki" and AC2.
- D-8 and D-9 attribute each opportunity to exactly one group, so the groups sum to the totals, and the plan tests the "second source" case the lesson asks for.
- D-6 validates metadata against `ActivityMetadata` before the insert (lesson) and needs no migration.
- The plan keeps the e2e suite at two specs and stays inside the module layering of `tech-stack.md`.
