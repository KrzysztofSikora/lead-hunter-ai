## Decisions the PR reviewer should look at
- D-5: `PrefilterRule` gains `source_filter` and `opportunities` gains a `prefilter_phrase` column. This is a persisted shape that S-18/S-19 inherit.
- D-1: the new `sources.filter_json` column (persisted shape, reused by S-18).
- D-8 together with finding #1: the HN default as specified by the roadmap is a no-op, and existing `hn-freelance` rows are not backfilled.
- D-9 / D-11: the Freelancer.com `?keyword=` URLs and the Arduino Discourse `.rss` URL are unverified, and so are Freelancer.com's terms. Human check 1 decides them.
- D-16: duplicates are rejected with a 400 rather than deduped. The API is strict and the UI dedupes before sending.

## What is good
- R1's blocker is fixed at the root (no transform in any response schema) and guarded twice: at the encoder level and at the HTTP serialiser.
- The rejection happens inside `signals.transaction`, only on `created`, and it reuses `prefilter_rule`. So the queue (`waiting`), `pendingWithoutPrefilter`, the requeue guard (`analysis-repository.ts:176-190`) and the live `rejected` counter (`job-run-repository.ts:175-177`) all hold without new checks.
- D-17 removes the event-shape drift risk by moving the helpers verbatim, which existing tests already cover.
- Withdrawn presets stay known for the access note (FR-04 AC7) without being offered (AC2). The `[FOLLOW-UP]` for elektroda.pl follows the roadmap rule instead of guessing.
- `UNVERIFIED` external facts are kept apart from verified ones, and a wrong URL fails loudly at run time through the robots.txt check.
