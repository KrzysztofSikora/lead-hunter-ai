# Plan: manual-text-import (S-03)

## Goal and end state
The operator pastes the text of a job post (optionally with its URL, which is stored but not
fetched; fetching is S-09) and gets a stored raw signal plus a `NEW` opportunity with
`analysisStatus = PENDING` that shows up in a filterable, sortable, paginated *Okazje* list.
Re-importing the same thing is recognised; a fresh install shows an honest empty state.

Observable when done:
- FR-02 AC1: `POST /api/signals/import` with text only stores a raw signal with
  `sourceType = manual_text`, `canonicalUrl = null`, `fetchedAt = now`, the text as snippet; no
  URL appears anywhere in the response or the row.
- FR-02 AC2 / FR-06 AC1: importing a URL a second time, or a variant that differs only in
  `utm_*`/`fbclid`/`gclid`/`ref`, fragment, trailing slash, default port or scheme/host case,
  returns 200 `{ result: "duplicate", opportunityId, matchedBy }`; still one signal and one
  opportunity. Same text without a URL twice → duplicate by content hash. The UI says
  "już zaimportowane" with a link to the existing opportunity.
- FR-02 AC3: every new opportunity is stored with `analysisStatus = PENDING`,
  `businessStatus = NEW`; S-04 picks these up without operator action.
- FR-02 AC4: empty/whitespace text without a URL, or text longer than `IMPORT_MAX_TEXT_CHARS`,
  gets 400 `ValidationError` and nothing is stored.
- FR-06 AC2: two imports with similar titles but different URLs and different text stay two
  opportunities.
- FR-06 AC3: every opportunity exposes its provenance as source facts (`source.type`, `url`,
  `title`, `snippet`, `publishedAt` = null, `fetchedAt`, `availability`, `lastVerifiedAt`) and
  keeps inferred values in a separate `analysis` group (null until S-04, `evidenceLevel` lives
  there).
- FR-11 AC1: `GET /api/opportunities` filters by minimum score, category, detection date range,
  source type and business status, sorts by score or date, and paginates; the *Okazje* view
  exposes all of it.
- FR-12 AC1 (list part): with no matching opportunity, the list shows "Brak zweryfikowanych
  okazji dla tego okresu", the number of sources checked and the adapter errors (0 and none
  until S-10/S-12), and no demo or generated opportunity.
- Data survives a restart (same database file, new app).

## Scope
- In: contracts for import, opportunity summary/detail/list; URL canonicalisation and content
  hash (pure, unit-tested); tables `raw_signals`, `opportunities`, `opportunity_evidence` with
  migration `0003_*`; signals module (import use case + route); opportunities module (list +
  detail + routes); `IMPORT_MAX_TEXT_CHARS` config; web views *Import*, *Okazje* (list with
  filters, sort, pagination, empty state) and a minimal read-only opportunity view
  `/okazje/:id` (provenance + evidence) as the target of the "już zaimportowane" link; one e2e
  test; README *Co działa*.
- Out: fetching the URL, robots.txt, SSRF guard (S-09); pre-filter, analysis, scoring, setting
  category/evidence level/score (S-04); the full §8 card and its actions (S-06, which extends
  `/okazje/:id`); status changes (S-08); `sources` table, `externalId` identity and job runs
  (S-10/S-12; see D-3); grouping several signals into one need (FR-30, P1); delete/export
  (S-15); TanStack Query (D-12).

## Decisions
| ID | Question | Chosen | Alternatives (and what they would buy) | Why | Reversal | Decided by |
|----|----------|--------|----------------------------------------|-----|----------|------------|
| D-1 | Opportunities per signal; what a duplicate does | One opportunity per distinct signal identity (`opportunities.primary_signal_id` unique). A duplicate import creates no signal and no opportunity; it adds an `opportunity_evidence` row (`REPEAT_IMPORT`) only when it brings something new: a canonical URL not yet recorded for that opportunity, or text whose content hash is not yet recorded. A URL-only repeat of a known URL adds nothing | B: duplicates add nothing (simpler, but drops the second URL/text the operator pasted, against the roadmap's "links its evidence"); C: always add a row (no rule, but repeated clicks pile up identical evidence) | Roadmap *Decided up front*; the "something new" rule keeps evidence meaningful | costly (data shape) | user (roadmap S-03) + agent |
| D-2 | Signal identity and normalisation | Identity order: canonical URL, then content hash (FR-06 AC1; `externalId` arrives with the first source that has one, D-3). Canonical URL per roadmap: lower-case scheme and host, drop fragment, default port, trailing slash on a non-root path, and query parameters `utm_*`, `fbclid`, `gclid`, `ref` (names matched case-insensitively); other parameters keep their order; an empty query loses `?`. URLs with user info (`user:pass@`) are rejected. Content hash = SHA-256 hex of the text after NFKC, lower-case, whitespace runs → one space, trim; `null` when there is no text | B: also sort query parameters and strip `www.` (catches more variants, but merges URLs the roadmap did not list and is hard to undo once stored); C: hash the raw text (no normalisation, misses copy-paste whitespace differences) | Follows the roadmap list exactly; normalised hash catches the common copy-paste variants | costly (stored identity values) | user (roadmap S-03) + agent |
| D-3 | Where the source of a signal is recorded before `sources` exists | `raw_signals.source_type` text (`manual_text` when no URL, `manual_url` when a URL is given, with or without text); no `sources` table and no `external_id` yet. S-10 adds `sources` and a nullable `source_id` FK plus `external_id` with a unique `(source_id, external_id)` index (additive `ALTER TABLE ADD COLUMN`) | B: create the full `sources` table now and seed a "manual" row (S-10's shape decided early, a fake source row in the list); C: `source_id` pointing at a seeded row only | Manual import has no configured source; everything later is additive | costly (data shape) | agent |
| D-4 | Storage of opportunities in this slice | `opportunities(id INTEGER PK, primary_signal_id UNIQUE FK, business_status TEXT 'NEW', analysis_status TEXT 'PENDING', category TEXT NULL, evidence_level TEXT NULL, score INTEGER NULL CHECK 0–100, confidence TEXT NULL, created_at, updated_at, last_verified_at NULL)`; indexes on `business_status`, `score`, `created_at`. | D-7 | Title and snippet of a manual signal | `snippet` = the text trimmed with CRLF → LF (whole text, AC1); `title` = first non-blank line, cut to 200 characters; URL-only import → `title` = the canonical URL, `snippet` = `''`. `publishedAt` = null, `availability` = `NOT_CHECKED`, `lastVerifiedAt` = null for every manual signal | B: an optional title field in the form (operator types it; one more input); C: title null (no derived value, but the list needs a label) | Title is a verbatim extract, not an inference; nothing about publication or availability is known, so it stays empty | cheap | agent |
| D-8 | How the DTO separates facts from inferences | Opportunity DTO groups fields: `source { type, url, title, snippet \| excerpt, publishedAt, fetchedAt, availability, lastVerifiedAt }` = source facts; `analysis { category, evidenceLevel, score, confidence } \| null` = model inferences and derived values, `null` until S-04 | B: flat fields plus a `fieldOrigins` map (flexible, but every consumer must look it up); C: flat fields only (FR-06 AC3 not expressed) | The structure itself states origin; S-04 extends `analysis` | costly (public API) | agent |

## Design

### Contracts (`packages/contracts/src/opportunities.ts`, exported from `index.ts`)
```
SourceType      = 'manual_text' | 'manual_url'                (S-10/S-11 add 'rss', 'imap')
BusinessStatus  = NEW | QUALIFIED | SAVED | OFFER_DRAFTED | CONTACTED | REPLIED | MEETING | WON | LOST
                  | REJECTED | EXPIRED | NEEDS_VERIFICATION    (brief §10.1)
AnalysisStatus  = PENDING | COMPLETE | FAILED
Category        = DIRECT_GIG | B2B_SUBCONTRACT | UNMET_NEED | PRODUCT_HYPOTHESIS | HARDWARE_IOT (§6.1)
EvidenceLevel   = DIRECT_REQUEST | EXPLICIT_PROBLEM | INDIRECT_SIGNAL | SPECULATIVE (§5.4)
Confidence      = LOW | MEDIUM | HIGH
Availability    = NOT_CHECKED | AVAILABLE | UNAVAILABLE
DEFAULT_IMPORT_MAX_TEXT_CHARS = 20_000
importRequestSchema(maxTextChars) = strict { text?: string max maxTextChars, url?: z.url({ protocol: /^https?$/ }) max 2048 }
                  refine: text?.trim() or url present, path ['text'], message 'wklej treść lub podaj adres URL'
ImportResult    = { result: 'created', opportunityId: int, signalId: int }
                | { result: 'duplicate', opportunityId: int, matchedBy: 'canonical_url' | 'content_hash', evidenceAdded: boolean }
SourceFacts     = { type, url: string|null, title, publishedAt: iso|null, fetchedAt: iso, availability, lastVerifiedAt: iso|null }
AnalysisSummary = { category|null, evidenceLevel|null, score: int 0–100|null, confidence|null }
OpportunitySummary = { id, businessStatus, analysisStatus, createdAt, updatedAt,
                       source: SourceFacts & { excerpt: string }, analysis: AnalysisSummary | null }
Evidence        = { id, type: 'IMPORT' | 'REPEAT_IMPORT', sourceFact: string, url: string|null, extractedAt }
OpportunityDetail = OpportunitySummary with source.snippet (full) instead of excerpt, plus evidence: Evidence[]
OpportunityListQuery = { page, pageSize, sort, minScore?, category?, sourceType?, status?, from?, to? } (coerced from strings)
OpportunityList = { items, page, pageSize, total, sources: { checked: int, errors: { source, message, at }[] } }
```

### Data (`apps/api/migrations/0003_*`, additive)
- `raw_signals(id INTEGER PK, source_type TEXT NOT NULL, canonical_url TEXT NULL UNIQUE,
  title TEXT NOT NULL, snippet TEXT NOT NULL, published_at INTEGER NULL, fetched_at INTEGER NOT
  NULL, content_hash TEXT NULL UNIQUE, availability TEXT NOT NULL, last_verified_at INTEGER
  NULL)`.
- `opportunities` as D-4, `primary_signal_id` → `raw_signals.id`.
- `opportunity_evidence(id INTEGER PK, opportunity_id FK ON DELETE CASCADE, raw_signal_id FK,
  evidence_type TEXT NOT NULL, source_fact TEXT NOT NULL, canonical_url TEXT NULL, content_hash
  TEXT NULL, extracted_at INTEGER NOT NULL)`, index on `opportunity_id`.

### Domain (`apps/api/src/modules/signals/identity.ts`, pure)
- `canonicalizeUrl(raw: string): string` (throws `InvalidUrlError` for non-http(s), user info,
  unparsable) per D-2.
- `contentHash(text: string): string | null` per D-2.
- `isNewEvidence(existing: { canonicalUrl, contentHash }[], candidate): boolean` per D-1.
- `deriveTitle(text: string, canonicalUrl: string | null): string` per D-7.

### Import use case (`modules/signals/service.ts`)
`importSignal({ text, url })` inside one repository transaction: canonicalise → find signal by
canonical URL → else by content hash → if found: maybe add `REPEAT_IMPORT` evidence (D-1) and
return `duplicate`; else insert signal, opportunity (`NEW`/`PENDING`) and `IMPORT` evidence and
return `created`. The unique indexes are the backstop; a unique-constraint error on insert is
re-read as a duplicate. Port `SignalRepository.transaction(fn)` exposes
`findSignalByUrl`, `findSignalByHash`, `opportunityForSignal`, `evidenceKeys(opportunityId)`,
`insertSignal`, `insertOpportunity`, `insertEvidence`. The pasted text is never logged.

### List and detail (`modules/opportunities/`)
`OpportunityRepository.list(query) → { rows, total }` and `get(id) → row + evidence | undefined`
(Drizzle query builder, filters as `and(...)`); service maps rows to DTOs (ISO times,
`analysis: null` while all four analysis columns are null). `SourceStatusReader.summary()`
(D-10) lives in `modules/opportunities/ports.ts`; its stub is in
`infrastructure/sources/source-status.ts`.

### Error model
| Case | Status | Body |
|------|--------|------|
| no session | 401 | `{ error: "unauthorized" }` (guard) |
| blank text and no URL, text too long, bad URL, unknown field, bad query value | 400 | `ValidationError` |
| URL with user info (rejected by `canonicalizeUrl`) | 400 | `ValidationError` with `path: "url"`, `code: "invalid_format"` |
| opportunity id not found | 404 | `{ error: "not_found" }` |

### Web (`apps/web/src/`)
Nav: *Start*, *Okazje*, *Import*, *Profil*. `/import`: textarea *Treść ogłoszenia*, input
*Adres URL (opcjonalnie)* with the hint "Adres zostanie zapisany jako źródło; pobieranie strony
dojdzie później — wklej treść.", button *Importuj*; result line "Zaimportowano — Zobacz okazję"
or "Już zaimportowane — Zobacz istniejącą okazję" (link to `/okazje/:id`), field errors by code.
`/okazje`: filter form (min. ocena, kategoria, źródło, status, od/do dates in Europe/Warsaw
converted to UTC instants), sort select, list items (title, source label, detection date in
Europe/Warsaw, status label, "Analiza: oczekuje", score "brak oceny" when null), pagination
*Poprzednia*/*Następna* with "Strona X z Y"; empty state "Brak zweryfikowanych okazji dla tego
okresu" + "Sprawdzone źródła: N" + errors or "Błędy źródeł: brak". `/okazje/:id`: source facts
labelled "ze źródła" (title, link or "wklejony tekst", dates, full text as plain text,
availability), analysis "brak analizy — w kolejce", evidence list. Source text is always
rendered as text (React escaping), never as HTML.

## Risks and unknowns
- drizzle-kit 0.31 must emit the `CHECK (score BETWEEN 0 AND 100)` and FK clauses; if not, the
  service enforces the range and a `[minor]` deviation is logged.
- The e2e uses the 4th of 5 login attempts per 15 minutes; a later e2e test needs a shared
  login (storage state) or will hit the throttle.
- Content-hash identity across URLs (D-2) treats an identical text posted at two URLs as one
  opportunity; the second URL is kept as evidence (D-1). Near-identical texts (one word
  changed) stay separate; grouping them is FR-30 (P1).
- S-09 will fill `snippet`/`content_hash` for URL-only signals after fetching; its hash may
  then collide with another signal. S-09 must handle that collision (merge as evidence); noted
  for its plan.
- `from`/`to` conversion of Warsaw dates is done in the browser; a wrong offset on DST days
  would shift the filter by an hour (human check covers a normal day only).
- `sources.checked = 0` is a stub (D-10) until S-10/S-12; if they forget to replace it, the
  empty state under-reports. S-12's plan must replace `source-status.ts`.
