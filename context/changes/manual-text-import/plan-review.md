## Decisions the PR reviewer should look at
- D-2 / D-8: storing only the canonical URL as the source URL (finding 1), and how the query string is rebuilt.
- D-14: `signal_identities` with first-owner-wins and URL-over-hash on conflict. This fixes how identity behaves for S-09/S-10.
- D-1: what a `REPEAT_IMPORT` evidence row stores (finding 3), since it is the only copy of a second pasted text.
- D-4: analysis columns on `opportunities` ahead of S-04.
- D-9 / D-10: the list query contract and the `sources { checked, errors }` stub, which S-12 must replace.

## What is good
- The R1 blocker is fixed at the right layer. A `PRIMARY KEY (kind, value)` lets SQLite enforce "one value → one opportunity", and the tests cover the cross-identity sequences that failed before.
- Every 400 now goes through the contract schema and the shared Zod handler, and OpenAPI shows the configured text limit.
- Findings are grounded and accurate: line references, `ENV_VARIABLES`, `openTestDb(dir)`, the `AppDeps.config` widening and the sync Drizzle transaction were all checked against the code.
- The scope stays tight. There is no `sources` table, no fetching and no TanStack Query, and each deferral names its owner (S-04, S-06, S-09, S-10/S-12).
- The e2e budget (4th of 5 logins, `routes.ts:18-19`; no new spec file) and the XSS/prompt-injection human check fit the repo rules.
