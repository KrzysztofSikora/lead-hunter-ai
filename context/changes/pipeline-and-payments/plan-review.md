## What is good
- The transition rule is one pure, shared `checkMove`, which makes it a clean TR-14 unit target. The alternatives are argued honestly.
- Contract data in the WON event's metadata follows the PRD data model ("metadata (e.g. contract value for a win)"). Payments are a separate append-only table with DB CHECKs, so WON ≠ paid holds structurally.
- The findings are accurate. I checked `status.ts:23` `operatorMoves`, the activity repository transaction, system moves only from `NEW` (`analysis-repository.ts:30`), the strict 409 literal, `startOfWarsawDay`, the 2026-10-25 and 2027-03-28 DST dates, the login throttle (max 5, smoke uses 4; the comment in `e2e/env.ts` that says 2 is stale and the plan fixes it), and `MockAgent.disableNetConnect()` in `apps/api/test/setup.ts`.
- The scope is tight. Out of scope is explicit (drafts, Today brief, payment edits), and the e2e evidence follows the "gate runs never rewrite committed files" lesson.
