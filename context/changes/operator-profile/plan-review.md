## Decisions the PR reviewer should look at
- D-5: changes the 400 body of every route, including login. It is a public contract and the main cross-cutting change in this item.
- D-2: the persisted and API profile shape (per-amount currency, enum lists). Later slices (pre-filter, scoring) build on it.
- D-1: profile stored as one JSON document with `schema_version`. Validation on read makes a bad row a hard 500 (finding 3).

## What is good
- Each AC is mapped to a concrete integration case. The table-driven AC3 cases check both the field path and "nothing stored".
- The costly decisions stay in few files: the contract in `contracts/profile.ts`, the error shape in `http-errors.ts`, storage in one table and one repository.
- Scope stays small: no TanStack Query, no PATCH, no profile consumers, and *Out of scope* is explicit.
- The plan follows the S-01 conventions (ports, repository wiring, the `Clock` move it had already planned) and uses the existing route-table and OpenAPI tests instead of writing new ones.
