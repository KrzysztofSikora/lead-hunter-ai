## Decisions the PR reviewer should look at
- D-2: nothing is stored on a failed fetch; AC4's "URL kept as the signal's source" is read as "kept in the form" (finding 3).
- D-4: allow-list on `unicast` only, so public NAT64/6to4 targets are refused too. Safe, but it is the security boundary.
- D-11: new stored `SourceType` value `manual_fetch` (public API and stored data).
- D-3: `FetchFailureReason` enum becomes public contract that S-10 will also use.

## What is good
- Grounding is strong. I checked undici 8.12.3 `lib/core/connect.js` (options are spread into `net`/`tls.connect`, so `connect.lookup` reaches the socket), the ipaddr.js 2.5.0 range tables, the cited contract lines, the lack of a CHECK constraint on `raw_signals.source_type`, the repo `origin` URL and the `devDependencies` placement of undici. All match.
- The IP-literal gap (Node skips `lookup` for literals) is spotted and closed by `checkTarget`. Checking at `connect.lookup` with no separate pre-resolution handles rebinding correctly.
- The test design (D-13) uses real loopback sockets with a fake resolver, so the connect path really runs, which `MockAgent` alone could not do.
- The duplicate check runs before the fetch, and identity is re-checked inside the synchronous transaction afterwards. This keeps D-14 of manual-text-import intact and keeps e2e offline.
- The contract change and the web label are in the same phase, so typecheck stays green. Robots behaviour follows RFC 9309.
