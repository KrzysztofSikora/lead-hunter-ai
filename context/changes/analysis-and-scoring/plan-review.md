## Decisions the PR reviewer should look at
- D-5: a new public `SKIPPED` enum value and system moves to `REJECTED` without history (with D-17).
- D-7: the stored analysis schema v1 shape (union, minor-unit money, extra fields).
- D-8: the `analyses` table plus ten denormalised opportunity columns (migration 0004).
- D-10: `LLM_PROVIDER` unset means not configured, against the tech-stack *Local development* line.
- D-13: the API applies no score minimum by default and unknown values pass the filters; "default 65" is only a one-click link.

## What is good
- Every covered AC maps to a named test in a named phase. The mutation targets match `test-plan.md` and `scripts/mutation-changed.sh`.
- Scoring, pre-filter and guard are pure and follow the tech-stack dependency direction. The rubric uses integer tables with exact sums and a stored version.
- The plan names the conflict with tech-stack (D-10) and the behaviour change in the e2e assertions instead of resolving them silently.
- The TR-02 test uses concrete canaries (password hash, `LEAK-CANARY`) and checks a data-only provider input.
- Scope stays tight: S-05/S-06/S-08/S-12 work is explicitly out, and rescoring is a `[FOLLOW-UP]`.
